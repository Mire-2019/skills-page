# 读画像指引（profile-reading）

适配改造（第 3 步）前，读用户的画像以判断「怎么改才贴合」。**读全，不只读一个全局记忆**；已确认 **profile 不进 skill**（锁版），每次装时现场取材。

## 读取步骤

1. **先读索引**：本地记忆目录的索引文件 `<YOUR_MEMORY_DIR>/MEMORY.md`（含全部记忆文件的路径索引）。
2. **按需读全相关文件**：凡文件名/内容与候选 skill 的领域、工作流、禁则相关的记忆文件**逐条读**。当前画像库结构：
   - **用户画像**：`user_*.md`——角色、交流方式（语言、业务语言、结论先行、证据分层）；
   - **反馈/工作方式**：`feedback_*.md`——工作方式、受众与语言、证据标准、会前准备、中文要求、HTML 交付（file://）、安全/凭据/工作盘原则、AI 成果克制；
   - **项目/业务**：`project_*.md`——各业务域痛点/链路速查；
   - **参考**：`reference_*.md`——skill 台账、联系人等。
3. **只取材不建快照**：每单会话现场读，不把画像固化成一个静态文件（避免过时 / 该 skill 自己成为死信源）。

## 怎么用画像推「适配」

| 画像维度 | 推论（示例） |
|---|---|
| 交流语言 | SKILL.md 正文/注释**全中文**（除非术语），输出表格结论先行 |
| HTML 交付 | 涉及产出 HTML 的 skill → 强制 file:// 可打开、预览面板交付 |
| 安全/凭据/工作盘 | 落盘一律工作盘；脚本禁系统盘、禁凭据进记忆/交付 |
| 证据标准 | 报告里每个判断给「证据分层」：事实/推断/待确认，不空口断言 |
| 业务域 | 与项目自有业务域（如协作/BI 等）无关的 skill 价值分偏低，除非通用型（检索、写作、效率） |

## 4 档适配类型（第 3 步选型参考）

| 档 | 定义 | 何时选 |
|---|---|---|
| **① 组装（默认）** | 外部系列拆散重组成本地一套模块 | 外部是大而全 series，本地要针对性模块 |
| **② 改造** | 改写外部 SKILL.md 运行逻辑（加约束/目录/命令） | 外部流程大体对，但要强调你的规条 |
| **③ 定制** | 外部只当参考模板，本地主力重建 | 外部是骨架思路，细节完全本地化 |
| **④ 只借鉴不装** | 无价值/重复/有风险 → 借鉴笔记进 report 库 | 判定不装但有点启发 |

**每次选型由用户拍板**，不默认固定档（①是默认起点但用户可改）。
