# 改造决策点清单（decision-points）

**用途**：skill-adapt 第 3 步「适配改造」的产出物之一。把拟对候选 skill 做的每一个改动，**在写正文之前**逐项列给用户拍板。改造决策前置，杜绝自作主张后返工。

> 反面教训（prompt-boost v1.1.0，2026-08-21）：当时自作主张砍掉被动识别模式、只给结论没给理由，用户一问「你没看明白/你直接干吧」才发现误判，只能重写成 v1.2.0。这个清单就是为堵住这类返工而设。

## 何时用

- 外部 skill 通过价值分析（值得装）→ 整合分析（有取舍）之后；
- 第 3 步定完改造类型（①②③④）后、**动 SKILL.md 之前**；
- 命中铁律 8「隐藏价值观」需剥壳/替换时（评分→自检、回流→模板库等），必列决策点。

## 清单模板

**关联**：源领域 `owner/repo#skill` + 本地改造名 + 目标改造类型

| # | 决策点 | 现状（原版）→ 建议（本地） | 原理 / 理由 | 不改会怎样 | 恢复原版代价 | 拍板 |
|---|--------|--------------------------|------------|-----------|--------------|------|
| 1 | 触发模式 | 被动+主动 → 仅主动（示例） | 被动需往全局记忆注入；与两阶段协议冲突 | 首轮会被未邀请引导 | 改回 description 一行 | ☐ |
| 2 | 记忆注入源 | 读 CLAUDE.md → 读本地 memory | 本环境无 session CLAUDE.md，约定在 memory | 预填内容悬空 | 删注入段 | ☐ |
| 3 | 标准体系 | 15 维评分 → 7 维自检（示例） | 原 15 维是作者价值观包装（铁律 8） | 引入异物价值观 | 还原文字段 | ☐ |
| … | | | | | | |

**填写规范**：
- **原理/理由**必须写全（这栏是清单的命门），不写「砍掉 XX」，而要写「为什么砍、基于本地哪条原则」；
- **恢复原版代价**给恢复成本（重写几段 / 一行 / 直接还原），降低你拍板时的心理负担；
- 拿不准的判断标 `[待确认]`，写进待确认清单，不要让我自己猜；
- 全部行拍板后才进入第 3 步写正文；有行被否 → 该行按你的意思改后再继续。

## 完成后

- 通过 ①目录结构 ②frontmatter 契约 ③关键命令 三重验证；
- 台账（skill-reports/一单）记录：决策点清单结论 + 实际改动 + 验证结果。
